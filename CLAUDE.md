# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Boxed is a BentoBox GameModeAddon for Minecraft (Paper) where each player is confined to a small expandable box. Completing Minecraft advancements grows the box. Built against `bentobox` 3.25.0-SNAPSHOT, Paper API 26.3, Java 25.

## Build / Test

- Build (default goal is `clean package`): `mvn clean package`
- Run all tests: `mvn test`
- Run a single test class: `mvn test -Dtest=AdvancementsManagerTest`
- Run a single test method: `mvn test -Dtest=AdvancementsManagerTest#testMethodName`
- Jacoco coverage report is generated as part of the build (`target/site/jacoco/`).

The `build.version` property in `pom.xml` is the canonical version. The `ci` and `master` Maven profiles activate from Jenkins env vars (`BUILD_NUMBER`, `GIT_BRANCH=origin/master`) to compute the final artifact name; don't hand-edit `revision`.

Surefire is configured with a long list of `--add-opens` JVM args required by Mockito's inline mock maker on Java 21+ — if you add new tests that touch JDK internals, extend that `argLine` in `pom.xml` rather than fighting module access errors locally. The `maven-compiler-plugin` runs with `<fork>true</fork>` to work around a JDK 25 in-process javac NPE (`this.hashes is null`).

## Architecture

Boxed is a BentoBox addon, not a standalone plugin. `Boxed` extends `GameModeAddon` and is loaded by BentoBox at runtime. `BoxedPladdon` is the Paper plugin-loader shim so Paper recognises the jar.

### The "seed world -> template -> game world" generator model

This is the core concept and touches almost everything:

1. **Seed world** (`<worldname>/seed`, and `/seed_nether`): a real vanilla-ish world generated using `BoxedSeedChunkGenerator` + `SeedBiomeGenerator` / `NetherSeedBiomeGenerator`. It's where Minecraft's normal terrain + structures actually get generated by the server. It is only loaded when a template has to be built.
2. **Template** (`generators/template`): `TemplateBuilder` captures every chunk inside `islandDistance` of the seed world into a `.bxt` file (`<data folder>/areas/<area>/normal.bxt`, `nether.bxt`) and `Boxed.loadTemplate()` then unloads the seed world. This happens once; later boots only open the file. `Template` reads block data from disk on demand (LRU of decoded `TemplateChunk`s) and keeps all biomes in memory. Deleting the `.bxt` files forces a rebuild.
3. **Game world** (`<worldname>`, `<worldname>_nether`): the world players actually play in. `BoxedChunkGenerator` does **not** generate terrain; it copies the template chunk at `repeatCalc(chunkX), repeatCalc(chunkZ)`, so every box is identical. `AbstractCopyBiomeProvider` and `BoxedBlockPopulator` read the same template.

Never hold the whole region in memory or load the seed world on a normal boot — that is what made old versions need 12 GB and 10 minutes. Biome providers must return an accurate `getBiomes()` list: if a Nether provider claims overworld biomes are possible, the server searches for stronghold biomes before generating any chunk, which takes minutes. Any change to world generation, structure handling, or world naming must respect the seed world, the template format (`TemplateFile` magic/version) and the game world. The `generatorMaps` / `generatorMap` fields in `Boxed.java` route world names → generators for `getDefaultWorldGenerator` (used by Multiverse and similar world-management plugins) and for the hook in `allLoaded()` that calls `WorldManagementHook.registerWorld`.

### Areas

`areas/AreaManager` loads `areas.yml`. Each `Area` (seed, biomes file, structures file) has its own seed worlds (`<worldname>/seed_<id>`), its own templates (`areas/<id>/*.bxt`) and owns one east-west **row** of the box grid, persisted in `areas/grid.yml` and never reassigned. The generator, biome provider and populator pick the template from the chunk's z alone (`AbstractBoxedChunkGenerator.rowCalc` -> `Boxed.getTemplate(env, chunkZ)`), so anything that generates chunks must pass real game-world chunk coordinates, not folded ones. Boxes are placed by `AreaLocationStrategy`, returned from `Boxed.getNewIslandLocationStrategy(user, bundle)` (a BentoBox 3.25.0 hook): the blueprint bundle's unique id names the area, unknown bundles use `default`. The y of a box's centre comes from `areas/BoxHeight`: BentoBox pastes the starter blueprint with its bedrock at the centre, so the centre is set to land the blueprint's `[spawn_here]` sign on the area's ground (read from the template; falls back to the island-height setting). The nether blueprint is pasted at the same y, so it only lines up where the nether ground happens to match. Structure lists are per area via `Boxed.getStructuresFile(location)`. `AreaRules` refuses a box (by throwing from the hook, before anything is created) when the area is closed (`enabled: false`), is waiting for a restart, or is chained (`requires` + the required area's `unlocks-next-at` box size) and not yet unlocked, or the player already has a box in that area (one per area; the box being reset does not count). `/boxadmin areas` (`AdminAreasCommand`) lists, visits, creates and requests rebuilds of areas; creating and rebuilding only take effect at the next start because templates are built in `createWorlds()`.

### Reachability

`reach/` answers whether an area can be played. `LandSurvey` counts, per box size, the blocks, biomes and template entities of an area's templates plus the starter blueprint and the structures file. `Requirements` reads `requirements.yml`, a hand-written model of what each scored advancement needs (and `provides` rules that turn biomes and structures into mobs). `GrowthSimulator` earns everything in reach, grows the box by the scores and repeats; `ReachReport` writes it up. `reach/StarterBounty` is what the starter blueprint gives a new box: its blocks and the items in its chests (counted as blocks by name, so `block:coal` is met by coal in the chest). `AreaCheck` adds the whole blueprint; the spot finder and scorer add only what is within 20 blocks above or below the `[spawn_here]` sign (`StarterBounty.NEAR_SIGN`), so a place does not need what a box is given anyway, and `SpotFinder.setNeedWood(false)` lets it look outside forests when the blueprint has a tree or sapling. `requirements.yml` `always` is a map of mob to the box size that gives it room (mobs do not spawn outside a box or within 24 blocks of a player); the sizes are estimates. The check also plays out a box with the blueprint alone and reports what that earns. `/boxadmin areas check <area>` runs the survey off the main thread. Every advancement with a score in `advancements.yml` must have an entry in `requirements.yml` (a test enforces it).

### Finding a place to start

`/boxadmin areas find <area> [seed|random] [radius]` (`AdminAreasFindCommand`) looks for good spots in a seed. `reach/SpotFinder` searches the vanilla biomes (no chunks needed) for wooded land with water nearby; the best few are generated in a throwaway `<worldname>/finder_<time>` world, using the area's biomes file laid out around every spot at once (`AbstractSeedBiomeProvider.setCentres`), and scored by `reach/SpotSurvey` (dry middle, then the box size that takes in logs, surface water, shallow stone, iron ore and coal). The world is unloaded without saving and deleted. An area uses a spot through `centre: x,z` in `areas.yml` (`Area.centreX/centreZ`) and `nether-centre: x,z` for the Nether. Fortresses have no structure templates, so they can only come from the land: after the overworld, the command locates the nearest fortresses in a throwaway Nether, generates each and uses `reach/FortressSpot` to suggest a `nether-centre` on open ground just clear of a blaze spawner.

`listeners/FortressMobsListener` makes a copied fortress work: natural spawns on nether bricks in the game Nether are swapped for wither skeletons, blazes and skeletons at vanilla fortress weights (`world.nether.fortress-mobs`). `LandSurvey` records spawners as the mob they make, and `requirements.yml` treats nether bricks as the fortress.

### Biome styles and the area workshop

`generators/biomes/BiomeLayout` reads one dimension of a biomes file and answers "which chosen biome is at dx,dz from the middle" (null = the seed's own). It supports per-quarter lists, `rings`, random `patches`, and `blend` (noise that bends the edges). `AbstractSeedBiomeProvider` only adds the centres and the vanilla fallback. `biomes.yml` is the "original" style; `biomes/*.yml` are the others (`workshop/BiomeStyles` maps names to files). With `blend: 0` the original layout must stay exactly as it was, because existing areas depend on it.

`workshop/WorkshopManager` runs the one workshop: temporary worlds `<worldname>/workshop` and `/workshop_nether` (folders inside the game world's folder, like seed worlds) made with the seed generator, peaceful, spawn limits 0. Its state (`workshop/Workshop`: seed, biomes file, source area, centres, the players inside and the game mode each had outside) is saved to `areas/workshop.yml` on every change and reloaded, with the worlds, in `onEnable`. `listeners/WorkshopListener` forces creative on entry, restores the game mode on exit, respawns in place, and sends players home if the workshop was discarded while they were offline (`areas/displaced.yml`). `/boxadmin areas edit` (`AdminAreasEditCommand`) holds the logic and can be typed; `WorkshopDialogs` is only the Paper dialog UI on top, and cannot be unit tested under MockBukkit. When the workshop overworld is made, `WorkshopManager.scan` searches the vanilla biomes (`reach/SpotFinder`), stores the candidates as unscored `Workshop.Spot`s, calls `setCentres` with all of them (spot 0 is always the starting centre; the others are kept `4 * area radius` from it so layouts do not overlap) and scores them one at a time with `reach/SpotScorer` (shared with the find command). The spot list is saved after each score and the scan resumes after a restart; the centres must be set again before the world is created or new chunks would get the wrong biomes. `/boxadmin areas spots` (`AdminAreasSpotsCommand`) lists them and `select` sets `Workshop.setCentre`, teleports, and `showCentre` sends a fake diamond block and a per-player `WorldBorder`. `/boxadmin areas make` (`AdminAreasMakeCommand`, `workshop/AreaMaker`) turns the workshop into a live area in two parts. `prepare` copies each dimension with `TemplateBuilder.buildAsync` (one column of chunks per callback, so the server keeps ticking; the blocking `build` is only for startup) into `areas/workshop-build/` and runs `reach/AreaCheck` on the result. `finish` writes `areas.yml`, calls `AreaManager.put` (new row, or the same row when replacing an area that has no boxes), moves the files into `areas/<id>/`, `Boxed.setLand`, `registerSeedGenerators`, makes the blueprint bundle, queues `BoxCleaner.clean` for the row when land was replaced, and `WorkshopManager.keepAs` unloads the workshop worlds with a save and renames their folders to the area's seed worlds. Nothing here may need a restart. Still to build: the End.

The Nether has its own places (`Workshop.getSpots(Environment.NETHER)`), found when the workshop Nether is first made (`WorkshopManager.scanNether`): `reach/FortressFinder` (shared with the find command) locates up to three fortresses, generates 8 chunks around each and `FortressSpot` picks open ground just clear of a blaze spawner. The first entry is always the starting Nether centre, measured the same way. The provider's centres are set, before anything is generated, to the start plus every fortress at least `4 * area radius` from the other centres, and saved as `Workshop.getNetherLayout` so that later chunks and restarts use the same layout; the layout is centred on the fortress chunk, not on the place picked, so `rebuild regenerate` of such an area lays the Nether biomes out slightly differently. The list is only saved when the whole scan is done, so a scan cut short by a restart starts again. `/boxadmin areas spots` works on the Nether for a player standing in it or when `nether` is the first argument, and `WorkshopManager.select(player, env, index)` moves only that dimension's centre.

Biomes are added by hand as patches: `generators/biomes/BiomePatch` (a circle in seed world blocks with a noise-bent edge) and `BiomePatches` (newest wins; cave biomes only apply below the cave depth, others only above). `AbstractSeedBiomeProvider.setPatches` puts them on top of the layout. They are kept in `Workshop`, then in `areas.yml` (`patches`, `nether-patches`) and `AreaManager.getPatches`, and `Boxed.registerSeedGenerators` gives them to the seed generators. New workshop areas start with the `none` style (`BiomeStyles.SEED`). `/boxadmin areas biome` (`AdminAreasBiomeCommand`) reports the box's biomes (`workshop/BiomeSurveyor` loads every chunk of the box and counts biome cells into a `LandSurvey`; `reach/BiomeReport` compares that with the biome needs and `provides` rules of `requirements.yml`) and adds or removes patches. Land that is already generated cannot be regenerated in place without losing features that overhang from neighbouring chunks, so `WorkshopManager.setPatches` generates the region (patch reach plus one chunk) in a throwaway `<worldname>/workshop_tmp_<time>` world with the same seed and provider settings, and `workshop/LandCopier` copies what differs (blocks without physics, biomes, block entities) into the workshop world a few milliseconds per tick. The target chunks must hold plugin chunk tickets for the whole copy: `World.setBiome` silently does nothing in an unloaded chunk.

Structures are placed in the workshop with the ordinary `/boxadmin place` (`AdminPlaceStructureCommand` hands over to `WorkshopManager.placeStructure` when the player is in a workshop world; the console always works on the workshop overworld). `workshop/PlacedStructure` holds one in workshop world blocks and converts to and from structures file entries, which are measured from the box middle rounded down to a chunk corner. The list lives in `Workshop` (`structures`). The structure is put in the workshop world without entities and without jigsaw or structure block mobs, so the template has its blocks only; the structures file still lists it, so `NewAreaListener` places it again over the copy when a box is made, which is what makes the mobs, fresh loot and the bounding boxes used for structure advancements. `WorkshopManager.remake` (shared with biome patches) regenerates a region and then puts back the listed structures that touch it; removing a structure (`/boxadmin areas structures remove`, or `place undo`) is a remake around it. Starting from an area with the same seed reads its structures file and places the structures once the world is made (`Workshop.isToShow`). `AreaMaker` checks the land against `WorkshopManager.getStructuresConfig()` and writes it to the area's structures file, leaving out structures outside the box.

### Deleted boxes

`listeners/BoxCleaner` restores a deleted (soft-deleted, `isDeletable()`) box's whole position from the template — generated chunks only, both dimensions, within a 10 ms per tick budget — then removes the island record so `AreaLocationStrategy` can hand the position out again (it always takes the first position in the row with no record). Do not rely on BentoBox's region-file purge for Boxed: it only deletes a region when every position overlapping it is deletable, and 640-block positions always share 512-block regions with neighbours. Deleted boxes are re-queued from the island cache on `BentoBoxReadyEvent`, so no extra persistence is needed.

### Advancements drive box size

`AdvancementsManager` is the other key subsystem. Box growth is data-driven from `advancements.yml`: each advancement key maps to an integer "box growth" increment. `AdvancementListener` watches for player advancement events and asks the manager to update the island's protection-range. Per-island state lives in `objects/IslandAdvancements.java` (a BentoBox `DataObject` persisted via its database layer). `AdvancementsManager.save()` is called in `onDisable()` — any new cached state it holds should be flushed there too.

Boxed's extra advancements are built in (`advancements/`): `BuiltInAdvancements` reads the JSON files in the jar's `advancements/<namespace>/...` (`AdvancementFiles`, with files in the data folder's `advancements/` added or replacing them) and registers them in memory with `Bukkit.getUnsafe().loadAdvancements(map, false)` in `onEnable` and again on `ServerResourcesReloadedEvent`, because a data reload drops anything that did not come from a data pack. Nothing is written to the world. The files are in the Minecraft 26.3 format, which differs from older versions (conditions are single objects keyed by `type`, entity predicate keys are namespaced); use the server's own data as the reference, not memory. Tags can only come from a data pack, so `advancements/tags/<item|block|entity_type>/*.json` are Boxed's own lists and `AdvancementTags` writes `"#bentobox:x"` out as a full list (only in `items`, `blocks` and `minecraft:entity_type`), resolving nested `#minecraft:` tags through `Bukkit.getTag`. Things this route cannot do, which is why three advancements use the `impossible` trigger and are awarded by listeners in `BuiltInAdvancements`: damage type tags (there is no list form) and `loot_tables` (the registry is not available to `loadAdvancements`). Recipes cannot be registered this way either. One bad file makes the batch fail, so registration falls back to one at a time. A test checks that the shipped files are JSON, have parents that exist and name only lists that exist. Not yet verified in game: whether a player's progress in these survives a data reload while they are online.

Because advancements are per-world in vanilla but Boxed runs multiple worlds on one server, the **InvSwitcher** addon is required at runtime to keep advancements separate between worlds. The code logs a warning if InvSwitcher/Border aren't installed but does not hard-fail.

### Structures

`NewAreaListener` plus `objects/IslandStructures.java`, `BoxedJigsawBlock`, `BoxedStructureBlock`, and `ToBePlacedStructures` handle placing/tracking vanilla structures inside player boxes. `AdminPlaceStructureCommand` is the admin-side hook for manual placement. If you're adding structure logic, both the "captured from seed world" pathway and the "placed into player box" pathway need to stay in sync.

### Flags

`Boxed.MOVE_BOX` (protection flag, owner-only by default) and `Boxed.ALLOW_MOVE_BOX` (world setting) gate the enderpearl-box-teleport feature implemented in `EnderPearlListener`. They are scoped to this game mode only via `setGameModes(...)` in `onEnable()`, and `MOVE_BOX` is conditionally registered/unregistered depending on `ALLOW_MOVE_BOX` — keep that conditional registration intact if you touch flag setup.

### Resources packaged at build time

`pom.xml` filters `src/main/resources` but copies `structures/*.nbt`, `locales/*.yml`, and `blueprints/*.blu|*.json` unfiltered into the jar at specific targetPaths. New resource types need a matching `<resource>` block or they won't ship.

## Testing notes

Tests use JUnit 5 (Jupiter) + Mockito 5.20.0 `mockStatic` + MockBukkit (`v26.3` version 4.119.0 via jitpack.io). There is no PowerMock and no custom `ServerMocks` helper. All test classes extend `CommonTestSetup`, which:

- Calls `MockBukkit.mock()` and registers `Mockito.mockStatic(Bukkit.class, RETURNS_DEEP_STUBS)` — use the inherited `mockedBukkit` field to stub `Bukkit.*` calls rather than creating your own.
- Exposes ready-made `@Mock` fields (`plugin`, `mockPlayer`, `world`, `location`, `iwm`, `im`, `island`, `pim`, `itemFactory`, `inv`, `notifier`, `fm`, `spigot`, `hooksManager`, `bm`, `sch`, `lm`, `phm`) plus the MockBukkit `server` and `mockedUtil` statics. Don't re-declare these in subclasses.
- Forces `org.bukkit.Tag.LEAVES` to initialise **before** the static Bukkit mock is installed — if you touch tag-related code and see stale deep-stubs across tests, broaden that list in `CommonTestSetup`.

A small `WhiteBox` helper (reflection-based private static field setter) replaces PowerMock's `Whitebox.setInternalState`. Any test that needs its own `MockedStatic<...>` (e.g. `DatabaseSetup`, `User`) must create it **after** `super.setUp()` and close it via `closeOnDemand()` **before** `super.tearDown()` — the parent's `Mockito.framework().clearInlineMocks()` in tearDown will otherwise corrupt the local static.

Jacoco excludes `org/bukkit/Material*` to avoid "class too large to mock" failures; keep that exclusion if you rearrange the build section.
